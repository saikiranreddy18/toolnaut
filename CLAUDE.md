# CLAUDE.md — working agreement for automated agents

Read this before making any change. It applies to every agent workflow in
`.github/workflows/agent-*.yml` and to anyone using `@claude` on an issue or PR.

## What this project is

Toolnaut (toolnaut.xyz) — a role-aware AI-tool discovery platform. A 60-second
quiz maps a visitor's role, experience and goals to a personalised stack drawn
from a 700+ tool catalog, then gives them a 4-week guided roadmap. Free public
beta, pre-revenue, deployed on Vercel.

Two independent halves:

- **`src/`** — React 19 + Vite 6 SPA. `react-router-dom` v7, `framer-motion`,
  `@react-three/fiber` for the 3D galaxy. No backend: all user state lives in
  `localStorage` behind the modules in `src/state/`.
- **`radar/`** — a host-agnostic Node ESM pipeline (no framework) that discovers
  new AI tools daily from GitHub / Hacker News / Product Hunt / RSS, LLM-enriches
  them, and publishes to `public/tools.json`. Runs unattended, so reliability
  matters more than cleverness here.

## Hard rules

- **Never push to `master`.** Every change goes through a PR from a
  `bot/<agent>/<slug>` branch. Never merge your own PR.
- **Never edit the `version` field in `package.json`.** `.github/workflows/release.yml`
  owns it. Multiple agents bumping it means a conflict on every PR.
- **Never modify `.github/workflows/`.** If a workflow is wrong, open an issue.
- **One open PR per agent at a time.** Check before you start; exit if one exists.
- **No signal, no PR.** If there is no failing CI run and no `agent-fixable`
  issue, stop and do nothing. An idle hour is the correct outcome.
- **Smallest possible diff.** No drive-by refactors, no reformatting, no renames.
  If you notice something unrelated, open an issue instead.

## Verification — all three must pass before opening a PR

```
npm test        # radar pipeline tests (node --test)
npm run build   # vite build + service-worker cache stamp
npm run smoke   # renders every route in headless Chromium, fails on any console error
```

`npm run smoke` is the one that matters. A green `npm run build` says nothing
about whether the app renders.

## Things that are load-bearing and easy to break

- **`vite.config.js` `manualChunks`** — React is pinned to its own chunk on
  purpose. The object form of `manualChunks` pulls `react`/`react-dom` into the
  `three` chunk, which makes the ~850KB three.js bundle a blocking dependency of
  every route. CI asserts three.js is not modulepreloaded from the entry.
- **`public/sw.js` `__BUILD_ID__`** — replaced at build time by
  `scripts/stamp-sw.mjs`. Never hardcode a cache version; if `CACHE` stops
  changing per deploy the activate handler deletes nothing and returning users
  are pinned to the first build they ever loaded. CI asserts the stamp ran.
- **`public/tools.json`** — generated by `radar/scripts/sync-to-app.js` and
  committed, because Vercel builds from git. It must stay out of `.gitignore`.
- **Service worker fetch handler** — cache-first applies to `/assets/*` only.
  Everything else, `/tools.json` above all, must stay network-first.
- **`src/state/*`** — every `localStorage` read must tolerate the API throwing
  (Safari private mode, blocked site data), not just returning null.
- **`radar/scorecard.js`** — an unscored criterion must stay unscored. Do not
  give it a default, a midpoint, or an average of its neighbours: the weights
  renormalise over what was actually judged and `coverage` reports the gap. A
  defaulted score turns "we have no evidence" into "we checked, it's average",
  which is the one thing the scores must never say.
- **`src/utils/radarDisplay.js`** — `showsNumericScores()` is the gate that keeps
  a sparse scorecard from printing a headline number. A tool can score Utility
  100 off a single signal at 41% coverage; that figure is true and misleading,
  and people anchor on it whatever the badge beside it says. Never render
  `utility`/`trust` without asking this function first.
- **`radar/util/retry.js`** — 4xx other than 429 must not be retried.
- **`radar/store/jsonStore.js`** — `load()` rethrows anything that is not
  ENOENT. A corrupt store must abort the run, never silently become `[]` and
  overwrite good data.

## Style

No semicolons in `src/` and `radar/` (a few 3D files use them — match the file
you are in). Comments explain *why*, not *what*. Conventional commit subjects
(`fix:`, `feat:`, `perf:`, `chore:`) — `release.yml` derives the version bump
from them.
